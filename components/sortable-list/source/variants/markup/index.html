The markup is the data and the fallback

An ordinary <ol> goes in. No configuration object, no fetch. With scripting off it is still an ordered list, correctly numbered and completely readable — reordering is the enhancement, not the content.

data-sortable-name names a row for the announcement when its text would read badly out loud. data-sortable-handle puts the handle where you want it instead of where the component would. data-locked makes a row a wall.

A long list inside a scrolling box

Drag a row to the top or bottom edge and hold it there. The box follows, which is the only way a fifty-row list can be reordered past what fits on the screen. It runs on its own frame loop, because a pointer held still at the edge sends no events.

Why the name is worth setting

Without data-sortable-name the row above would be announced with its flag character read out first. The visible text stays exactly as the author wrote it; only what gets spoken changes.

What comes back out

order is the names in their current order and items is the same list with each row's index, lock state and element. A reorder event carries { from, to, order, name }.
