The second path, not an extra

Escape puts it back, it does not drop it

Pick a row up, move it three places, then press Escape. It returns to where it started, not to wherever it happened to be. A cancel that quietly commits the last position is worse than no cancel, because it teaches people not to trust it. pointercancel — a phone call, a system gesture — does the same thing.

Everything is spoken

Picking up, every move, the drop and the cancel each go through a role="status" region: "Grabbed Schedule the send, position 3 of 6", then "position 2 of 6", then "Dropped … at position 2 of 6". Without that the reordering happens somewhere a screen reader user cannot see.

Focus survives the move

The same nodes are re-inserted rather than rebuilt, so the handle you were on is still the handle you are on. Rebuild the rows and focus falls to the body, which strands anyone driving by keyboard.
