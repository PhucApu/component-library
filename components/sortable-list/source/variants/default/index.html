Not the HTML5 drag-and-drop API

That API does not fire on touch in most mobile browsers — on a phone the feature simply is not there. It also needs a preventDefault on dragover before a drop is allowed at all, and its drag image is a browser-rendered bitmap you cannot style. dataTransfer exists to move data between applications, which is not what reordering a list is. Pointer events give one code path for mouse, touch and pen.

A handle, and a threshold

A row that is draggable everywhere cannot have its text selected or its buttons pressed, so the handle is the default and drag="row" is the opt-in. Nothing moves until the pointer has travelled 5px, or pressing a button inside a row would register as a one-pixel drag and eat the click.

Rows are moved, not re-rendered

The same nodes are re-inserted in the new order, so focus stays on the handle you just used and anything living inside a row survives the move.
